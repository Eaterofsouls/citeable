AI answer engines routinely misrepresent brands, and there was no tool that closed the loop between "the AI said something wrong" and "here's the exact line of code that caused it."

Engineering War Story: The Citation Leak

During a system audit, I discovered a subtle but critical citation integrity bug: the synthesis engine was occasionally citing internal reference material (e.g., generic explanations of how AI crawling works) instead of client-specific evidence in its final remediation recommendations.

The Root Cause: The underlying SQL query in findings_to_claims.py::_lookup_claim fetched status and confidence, but never fetched claim_scope. The engine had a hard invariant: "no recommendation without a citing claim". That invariant was holding, but the claim it picked was legally correct and substantively wrong.

The Fix: I didn't just add a UI filter. I added a canonical is_client_evidence boolean directly into the SQLite schema via a GENERATED ALWAYS AS VIRTUAL column, indexed it, and updated the wiring layer to strictly refuse non-client evidence. Now, the bug is impossible by design, not just hidden by CSS.

Tech Stack & Scale

  • Data Layer: SQLite with strictly enforced CHECK constraints and triggers (e.g., RAISE(ABORT, 'Hard delete forbidden') — claims are only ever superseded, never destroyed).
  • Backend: Python, FastAPI, and a custom Synthesis Engine.
  • Frontend: Vanilla JS + HTML/CSS, implementing a custom unified design token system (areos-design-tokens.css) bridging dark-mode, responsive layouts, and robust micro-interactions without heavyweight frameworks.
  • Scale: Managing hundreds of interconnected knowledge claims across 7 pipeline stages, translating raw findings into prioritized, page-grouped remediation plans.
